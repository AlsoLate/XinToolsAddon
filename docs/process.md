# XinToolsAddon 执行步骤与工作流程

> 定义项目的标准工作流程：从需求到交付的每一步。所有开发工作按此流程执行。

## 1. 总体工作流程

```
需求提出 → 需求沟通确认 → 更新 requirements.md → 规划开发步骤
    → 开发实现 → 构建验证 → 更新文档 → 记录开发日志
```

## 2. 各阶段执行标准

### 2.1 需求阶段

1. 用户提出想法后，先整理需求并确认细节（触发方式、交互、范围等）。
2. 有不确定处必须向用户提问确认，不自行假设关键行为。
3. 确认后将需求写入 `docs/requirements.md`，状态标记 `✅ 已确认`。

### 2.2 规划阶段

1. 在 `docs/roadmap.md` 中规划分阶段开发步骤。
2. 原则：**小步推进**，每阶段只做一件事，完成并验证后再进入下一阶段。
3. 每阶段包含：目标、涉及文件、验证方式。

### 2.3 开发阶段

1. 遵循 `docs/design.md` 的代码规范。
2. 技术实现参考 `docs/technical.md`；遇到新 API 先核实再编码。
3. 每次修改范围控制在当前阶段目标内，不做无关改动。

### 2.4 构建验证阶段

1. 代码修改完成后运行 `./gradlew build`。
2. 编译错误必须当场修复，编译通过才算完成。
3. 涉及模块注册、mixin 配置的修改需检查对应 JSON/主类引用。

### 2.5 文档与日志阶段

1. 更新 `docs/technical.md`（回填实际实现）与 `docs/roadmap.md`（状态推进）。
2. 更新当日开发日志（`dev-log/YYYY-MM-DD.md`）：完成事项、待办事项、问题记录。

## 3. 开发日志记录规范

- 日志文件：`dev-log/YYYY-MM-DD.md`，每天一个文件。
- 必填内容：
  - **完成事项**：当天完成的开发/文档工作。
  - **待办事项**：下一步要做的事。
  - **问题记录**（可选）：遇到的问题与解决方案。
- 每次开发会话结束时更新当天日志；跨天继续工作时新建当天日志并沿用待办。

## 4. 每日工作流（会话驱动）

1. 打开项目 → 读取 `CLAUDE.md`（指引）→ 读取 `dev-log/` 最新日志（了解待办）。
2. 确认今天要执行的阶段（查 `docs/roadmap.md`）。
3. 开发 → 构建验证 → 更新文档 → 更新当日日志。

## 5. 构建命令速查

```bash
./gradlew build        # 编译打包（每次修改后必跑）
./gradlew runClient    # 运行客户端测试
./gradlew clean        # 清理构建缓存
```
